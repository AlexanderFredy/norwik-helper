## 1. Структура проекта

```

├── src/

│   ├── config.py            # загрузка .env
│   ├── bot/                 # Telegram-слой
│   │   ├── handlers.py      # обработчики сообщений и админ-команд
│   │   └── auth.py          # middleware whitelist-проверки
│   ├── agent/               # AI-оркестратор
│   │   ├── orchestrator.py  # цикл tool use с Claude API

├── .env.example
├── requirements.txt
├── Dockerfile

```

## 2. Фазы разработки

### Фаза 0 — Каркас проекта

| Задача | Детали |
|---|---|
| Инициализация | `git init`, структура каталогов по схеме выше |
| Зависимости | `requirements.txt`: aiogram, anthropic, openpyxl, python-docx, pdfplumber, httpx, beautifulsoup4, aiosqlite, python-dotenv |
| Конфигурация | `config.py` — загрузка переменных из `.env` (см. specs/master-spec.md, раздел 8); `.env.example` с шаблоном |

**Критерий готовности:** проект запускается, конфиг читается, отсутствующие переменные дают понятную ошибку.

---

### Фаза 1 — Telegram-бот + авторизация

| Задача | Детали |
|---|---|
| Бот-скелет | aiogram 3.x, режим polling |
| Whitelist | SQLite-таблица пользователей (`telegram_id`, `name`, `added_by`, `added_at`) через aiosqlite |
| Middleware авторизации | Пользователь не в whitelist и не админ → ответ «Доступ запрещён», запрос не обрабатывается |
| Админ-команды | `/adduser`, `/removeuser`, `/listusers` — доступны только `ADMIN_TELEGRAM_ID` из конфига |

**Критерий готовности:** бот отвечает; неавторизованный получает отказ; админ-команды управляют whitelist.

---

### Фаза 2 — Email Tool (mail.ru, IMAP, read-only)

| Задача | Детали |
|---|---|
| IMAP-клиент | `client.py`: IMAP SSL `imap.mail.ru:993`, пароль приложения. **Только чтение**: `select(readonly=True)`, разрешены только SEARCH/FETCH; STORE, APPEND, EXPUNGE, отправка — не реализуются вовсе |
| Поиск писем | Фильтры: отправитель, тема, дата, текст |
| Парсеры вложений | `attachments.py`: `.xlsx` — openpyxl, `.docx` — python-docx, `.pdf` — pdfplumber, `.csv`/`.txt` — stdlib. Легаси-форматы `.doc`/`.xls` — конвертация (LibreOffice headless) либо явное предупреждение в логе и ответе |
| Классификатор | `classifier.py`: тип письма (прайс/остатки) по приоритету: тема → имя вложения → названия листов Excel (ключевые слова — specs/master-spec.md, раздел 4) |
| Парсер подписи | Извлечение телефона и имени менеджера из блока после `--` или «С уважением» |

**Критерий готовности:** интеграционный скрипт подключается к реальному ящику, находит последний прайс и последние остатки тестового поставщика, читает вложения.

---

### Фаза 3 — Website Tool (norwik.ru)

| Задача | Детали |
|---|---|
| Разведка поиска | **Первая задача фазы** — определить реальный URL/механику поиска на norwik.ru (в spec помечено «уточнить при реализации») |
| Поиск по названию | httpx + BeautifulSoup, парсинг выдачи: название, ID, URL карточки |
| Переход по ID | `https://www.norwik.ru/item/{id}` |
| Парсинг карточки | Цена продажи; ID из `<div class="property">ID: <strong>…</strong></div>` или URL |

**Критерий готовности:** по тестовому ID `2140` возвращаются цена и ссылка; поиск по названию находит товар.

---

### Фаза 4 — AI-оркестратор (Claude API, tool use)

| Задача | Детали |
|---|---|
| Инструменты модели | `tools.py`: `search_emails`, `read_email`, `read_attachment`, `search_norwik`, `get_norwik_product` |
| Цикл tool use | `orchestrator.py`: запрос менеджера → цикл вызовов инструментов → финальный текст для Telegram |
| Системный промпт | `prompts.py` кодирует логику spec (разделы 3, 6): валидация полноты запроса (бренд + коллекция/артикул; размер для плитки) → уточняющий вопрос без поиска; ветвления: основной сценарий / случай А / случай Б / случай В; точные форматы ответов |
| Web search (случай А) | Встроенный web search tool Claude API — поиск сайта производителя/дистрибьютора, когда в почте нет ни товара, ни бренда |

**Критерий готовности:**
- полный запрос → ответ в формате spec;
- неполный запрос (только бренд) → уточняющий вопрос;
- кейсы А/Б/В отрабатывают по сводной таблице ветвлений из spec.

---

### Фаза 5 — Интеграция и деплой

| Задача | Детали |
|---|---|
| Связка | Сообщение в боте → оркестратор → ответ; индикатор «печатает…» на время обработки |
| Обработка ошибок | IMAP недоступен, сайт не отвечает, таймаут модели → понятное сообщение пользователю, детали в лог |
| Контейнеризация | Dockerfile + docker-compose; volume для SQLite-базы |
| Деплой | Облачный VPS, автозапуск контейнера, логирование |

**Критерий готовности:** end-to-end сценарий из Telegram работает на сервере.

## 4. Верификация

### Юнит-тесты
- `classifier.py` — определение типа письма по теме / имени вложения / листам Excel
- Парсер подписи — разные форматы подписей поставщиков
- Парсер карточки norwik.ru — на сохранённом HTML (без сетевых вызовов)

### Интеграционные тесты
- Чтение реального ящика mail.ru (тестовый поставщик)
- Поиск товара на norwik.ru по ID `2140`

### E2E чек-лист
1. Неавторизованный пользователь → «Доступ запрещён»
2. Неполный запрос («Ламинат Kronospan 33 класс») → уточняющий вопрос
3. Полный запрос → ответ в формате spec с поставщиками, остатками, ценами и ссылкой на сайт
4. Товар отсутствует, бренд есть в почте → случай Б (список поставщиков бренда)
5. Ни товара, ни бренда → случай А (ссылка на сайт производителя)
6. Товар есть в почте, нет на сайте → случай В
