Мы разрабатываем модель рабочего процесса агента, который находится в режиме обработки прайсов.
Модель позвояет жестко отслеживать состояние всех прайсов полученных агентом и выполнение задач по каждому прайсу.
Эта модель не должна никак зависеть от визуала, который с ней работает (сейчас это ТГ и 1С).
Модель должна иметь набор методов, с помощью которых визуал можем менять её состояние.
Также у самой можели должны быть методы, которыми она обновляет визуал. 
Агент должен иметь возможность сохранять в своей БД состояние модели, извлекать это состояние из БД в оперативную память.
Сохранение нужно делать при каждом изменении состояния модели,
чтобы избежать потери данных и рассинхронизаций в случае остановки VPS агента, либо сбоев в рабтоте визуала.
Основа модели - это список прайсов поставщиков, которые требуют обработки.

Описание класса ПРАЙС, из которых состоит этот "Список прайсов":

Поля класса ПРАЙС:
-прайс поставщика - объект класса "Представление прайса постащика", который хранит данные о прайсе поставщика (Название поставщика, список ТМ в прайсе),
 полученный агентом, имеет внутри себя дату получения (это не дата, которая можем быть внутри прайса).
мы сознательно не говорим откуда пришёл прайс, источники могут быть разными, пока это почта и  прямая отправка админом в ТГ.
У данного класса должна быть ссылка на сам файл прайса, который хранится на сервере агента.
Также у данного класса должно быть поле на ссылку сущности поставщика (берется по уже разработанным нами механизмам, таже хранятся в БД агента)
Без ссылки на файл-прайса объект данного класса существовать не должен. Нужно контролировать удаление файла с сервера. Если в модели есть такие объекты - 
удаление файлов прайсов, на которые они ссылаются, нужно блокировать

-дата создания - когда агент создал данный экземпляр класса (может не совпадать с датой получения прайса).
Пример: письмо с прайсом пришло на почту вчера (это дата получения прайса), а агент нашёл его и создал объект в списке сегодня,
это и есть дата создания.

-Статус - это фискированный enum, со значениями: "к обрабоке", "выполнен", "частично обработан"

-Признак наличия Более свежего прайса (булево) - что есть более новый прайс ТОГО ЖЕ поставщика. Агент меняет этот флаг в существующем объекте списка, когда
добавляет в писок такой прайс.
- Ссылка на более новый прайс - ссылка на объект нового прайса такого же класса "Прайс" и этого же списка. Может существоваь пока этот объект в списке,
если объект был удален из списка - ссылка на него в других объектах очищается, Признак по сути отражает наличие данной ссылки,
если нет ссылки - false, если есть какая то ссылка - true.

-список задач по прайсу - это список другого класса - "Задача по прайсу"
{
    Поля класса "Задача по прайсу":
    - дата создания - тип дата и время
    - Название задачи: - фискированный enum: "нормализация наименований", "изменение свойств", "Добавление новых", "Удаление отсутствущих в прайсе", "изменение цен"
    - Предмет: - фискированный enum: "коллекция", "товар"
    - Статус: - фискированный enum: "к обрабоке", "выполнена", "частично обработана".
    - Описание: - строка, в которую агент кладет краткое описание, что нужно сделать.
    - Результат выполнения: - строка, в которую агент кладет краткое описание результата выполнения.
    - Дата выполнения: - системная дата, когда последний раз был изменен стату на "выполнена" или "частично обработана".

    При создании нового объекта класса "Задача по прайсу":
    Агент заполяет название, предмет, описание, результат по умолчанию пустой, статус - "к обрабоке",
    дата создания - текущую системную дату и время.
    Дата выполнения - пустая.

    Методы класса "Задача по прайсу":
    - Выполнить задачу - меняет статус на "выполнена", "частично обработана". Решение со статусом принимает агент, он же заполяет краткое описание результата и обновляет Дата выполнения.
    - Измененить описание - админ, работая с визуалом, может вносить свои правки в описание, которое агент должен учитывать при получении команды на выполнение задачи
    - Уничтожить задачу - уничтожить полностью задачу как сущность.
    - Вернуть в обработку - меняет статус на "к обрабоке". Очищает Дата выполнения. 
}

При создании нового объекта класса "ПРАЙС" заполняем поля:
- прайс поставщика - если этой сущности нет (агент не смог её создать), то создания не объекта "ПРАЙС" проиходит,
- дата создания - текущей системной датой,
- статус - "к обрабоке",
- признак наличия Более свежего прайса - при создании должен быть false. В принципе не должны создаваться объекты
"ПРАЙС" и добавляться в список, если в нём есть уже более новые прайсы ТОГО ЖЕ поставщика (проверить случай, 
когда поставщик разделает прайсы на разные файлы по типам товаров, например. Такие прайсы агент не должн "склеивать" в одну сущность).
Признак свежего прайса может быть изменен на true, только позже, когда данный объект уже есть в "Список прайсов" и появился более новый прайс.
- Ссылка на более новый прайс - null, также по выше описанной логике.
-список задач по прайсу - формируется и заполняется агентом объектами класса "Задача по прайсу". Задачи в списке сортируются по типу в последовательности:
 "нормализация наименований", "изменение свойств", "Удаление отсутствущих в прайсе", "Добавление новых", "изменение цен".


Методы класса ПРАЙС:
- Выполнить - меняет статус на "выполнен", если выполнены ВСЕ задачи из списка задач по прайсу. 
  на статус "частично обработан", если выполена хотя бы одна задача из списка.
- Добавить более новый прайс - меняет поля Признак наличия Более свежего прайса и Ссылка на более новый прайс 
по вышеописанной логике
- Очистить Ссылку на более новый прайс - закладываем этот метод, на случай, если более новый прайс был добавлен ошибочно и нужно это исправить
 он скидывает Признак наличия Более свежего прайса в false и очищает ссылку на более свежий прайс
- Добавить новую задачу в список задач по прайсу
- удалить задачу из списка задач по прайсу
- Обновить список задач - агент заново формирует задачи по данному прайсу, очищает текущий список и заполняет его заново
- Уничтожить прайс - уничтожить как сущность, таже уничтожаем все объекты "Задача по прайсу" из его списка. удаляем уже пустую ссылку из списка обработки "Список прайсов".

Методы самог верхнего класса, который содержит "Список прайсов":
- набор методов, которые позволяют агенту работать с этим списком (добавлять, удалять, вносить изменения)
- набор методов, которые будут обновлять визуал, приизменениях модели

ВАЖНО: Сам визуал может только отправлять команды в модель, вида "Выполни такю-то задачу", которая содержится в списке
"список задач по прайсу" объекта "Прайс". Все изменения состояния модели производит сам агент. Если сотсояние изменилось,
то вызывается метод на обновление визула (сделать кодом, без участия LLM агнета)
