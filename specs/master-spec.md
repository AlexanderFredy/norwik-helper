# Спецификация: Агент-помощник менеджера интернет-магазина

## 1. Обзор системы

Облачный AI-агент с Telegram-ботом как точкой входа. Помогает менеджеру быстро узнать: у каких поставщиков есть товар, сколько его на остатке, по какой цене закупать, и сколько он стоит на сайте магазина.

---

## 2. Архитектура

```
Telegram (менеджер) ──► Telegram Bot ──► AI Agent (оркестратор)
                                              │
                          ┌───────────────────┼────────────────────┐
                          │                   │                    │
                   Email Tool           Website Tool          User Store
                  mail.ru IMAP          norwik.ru             SQLite
                  (read-only)           (парсинг)             (whitelist)
```

---

## 3. Компонент: Telegram-бот

### Авторизация
- Список разрешённых пользователей хранится в БД (whitelist)
- Администратор задаётся как фиксированный `ADMIN_TELEGRAM_ID` в конфигурационном файле `.env`
- Все остальные пользователи получают ответ: `"Доступ запрещён"`

### Команды администратора

| Команда | Описание |
|---|---|
| `/adduser <telegram_id>` | Добавить пользователя в whitelist |
| `/removeuser <telegram_id>` | Убрать пользователя из whitelist |
| `/listusers` | Показать список разрешённых пользователей |

### Запросы менеджера

Произвольный текст. Запрос считается **достаточным**, если в нём присутствуют:

| Категория товара | Обязательные поля | Дополнительно (уточняется при отсутствии) |
|---|---|---|
| Ламинат / напольные покрытия | Бренд + коллекция или артикул | Класс, толщина |
| Керамическая плитка | Бренд + коллекция или артикул | Размер (напр. 30×60) |
| Двери | Бренд + модель или артикул | Размер полотна |

Если запрос **не позволяет однозначно идентифицировать товар** (например, указан только бренд без коллекции или артикула), агент **не выполняет поиск**, а возвращает уточняющий вопрос.

**Примеры некорректных запросов и реакция агента:**

| Запрос менеджера | Ответ агента |
|---|---|
| `"Ламинат Kronospan 33 класс 1,5 м²"` | `"Уточните, пожалуйста: коллекцию или артикул ламината Kronospan (например: «Kronospan Castello 8633», артикул 8633)"` |
| `"плитка Kerama Marazzi белая глянец 10 упаковок"` | `"Уточните коллекцию/артикул и размер плитки Kerama Marazzi (например: «Авеллино белый 7×7», арт. 2828)"` |

**Примеры корректных запросов:**

- `"Ламинат Kronospan Castello 8633, 33 класс, 1,5 м²"`
- `"Плитка Kerama Marazzi Авеллино белый 7×7 арт.2828, 10 упаковок"`
- `"Дверь Profil Doors Серия X модель X-5, 2 шт."`

## 4. Компонент: Email Tool (mail.ru, IMAP, read-only)

### Подключение
- Протокол: IMAP SSL, `imap.mail.ru:993`
- Авторизация: пароль приложения (создаётся в настройках mail.ru)
- **Только чтение** — запись, удаление, отправка, изменение настроек запрещены

### Функции
- Получение списка писем с фильтрацией по отправителю / теме / дате
- Чтение тела письма и вложений
- **Поддерживаемые форматы вложений:** `.xls`, `.xlsx`, `.doc`, `.docx`, `.pdf`, `.csv`, `.txt`

### Идентификация типа письма (прайс vs остатки)

Порядок проверки:
1. **Тема письма** — ключевые слова: `прайс`, `price`, `цены` → прайс-лист; `остатки`, `остаток`, `склад`, `наличие`, `stock` → остатки
2. **Название вложения** — аналогичные ключевые слова в имени файла
3. **Если Excel и тип не определён** — смотреть названия листов в книге

### Извлечение данных о поставщике
- Телефон и имя менеджера парсятся из **подписи письма** (блок после `--` или `С уважением`)
- Email отправителя берётся из заголовка `From`

---

## 5. Компонент: Website Tool (norwik.ru)

### Поиск по названию
- URL поиска: `https://www.norwik.ru/search?q={запрос}` (уточнить при реализации)
- Парсинг результатов: название товара, ID, URL карточки

### Поиск по ID
- Прямой переход: `https://www.norwik.ru/item/{id}`

### Извлечение данных с карточки товара
- Текущая цена продажи
- ID товара из `<div class="property">ID: <strong>…</strong></div>` или URL

## 6. Алгоритм обработки запроса менеджера

```
1. Извлечь из запроса: [название товара], [количество], [ед. изм.]
2. Валидация запроса:
   - Проверить наличие бренда + коллекции/артикула (и размера для плитки)
   - Если данных недостаточно → вернуть уточняющий вопрос, остановиться
3. Поиск в почте:
   а. Найти все письма, где упоминается название/артикул товара
   б. Сгруппировать по поставщику (email отправителя)
   в. Параллельно: найти письма, где упоминается только бренд (без конкретного товара)
4. Ветвление по результатам поиска — см. раздел «Случаи неполных результатов» ниже
5. Для каждого найденного поставщика товара:
   а. Найти последнее письмо с остатками → {дата, кол-во, ед. изм.}
   б. Найти последнее письмо с прайсом → {дата, цена, ед. изм.}
   в. Извлечь контакты из подписи → {имя, телефон, email}
6. Найти товар на norwik.ru → {ссылка на карточку товара на сайте, цена на сайте}
7. Сформировать ответ
```

### Формат ответа — основной сценарий

```
По вашему запросу «{название товара}» есть следующие поставщики:

1. {Наименование}, {email}, {телефон}, {имя менеджера}
   На остатке от {дата}: {кол-во} {ед. изм.}
   Закупочная цена: {цена} {ед. изм.} (прайс от {дата})

2. ...

Цена на сайте сейчас: {цена} {ед. изм.} {ссылка на карточку товара на сайте}
```

---

### Случаи неполных результатов

#### Случай А: Товар не найден в почте, поставщиков бренда тоже нет

Агент выполняет поиск в интернете сайта производителя или официального дистрибьютора данного бренда/товара (через web search).

Ответ:
```
Я не нашёл в почте подходящих поставщиков.
Но есть сайт производителя/дистрибьютора данного товара: {ссылка на страницу с подходящим товаром}
```

#### Случай Б: Конкретный товар не найден, но в почте есть поставщики этого бренда

Ответ:
```
Данного товара я не нашёл, но эти поставщики занимаются продажей данного бренда:

1. {Наименование}, {email}, {телефон}, {имя менеджера}
2. ...
```

#### Случай В: Товар найден в почте, но не найден на сайте norwik.ru

Ответ выводится в основном формате, строка о цене на сайте заменяется:
```
Цена на сайте: товар не найден на norwik.ru
```

#### Сводная таблица ветвлений

| Товар в почте | Бренд в почте | Действие |
|---|---|---|
| Найден | — | Основной сценарий |
| Не найден | Найден | Случай Б — список поставщиков бренда |
| Не найден | Не найден | Случай А — поиск сайта производителя в интернете |

## 7. Технический стек

| Слой | Технология |
|---|---|
| AI-оркестратор | Python + Claude API (tool use) |
| Telegram-бот | `aiogram 3.x` |
| Почта | `imaplib` + `email` (stdlib) |
| Парсинг Excel | `openpyxl` |
| Парсинг Word | `python-docx` |
| Парсинг PDF | `pdfplumber` |
| Парсинг сайта | `httpx` + `BeautifulSoup4` |
| БД пользователей | `SQLite` (через `aiosqlite`) |
| Конфигурация | `.env` файл (`python-dotenv`) |
| Деплой | Docker + облачный VPS |


---

## 9. Ограничения

- Агент не кэширует прайсы и остатки — читает актуальные письма при каждом запросе
- Точность парсинга подписи зависит от формата, который используют поставщики — возможны случаи, когда данные не распознаются
- Поиск товара по названию нечёткий — финальный матч выполняет AI
